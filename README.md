# HighlighterCS2

Находит яркие моменты в демках Counter-Strike 2 и записывает их в готовые `.mp4`.

Вы отдаёте `.dem`, выбираете из таблицы нужные моменты, забираете нарезанные клипы. Без CSDM и без устаревших плагинов: парсинг демки на `demoparser2` с ядром на Rust, запись через HLAE, сведение через ffmpeg.

```
demo.dem  ->  парсинг  ->  детекция  ->  таблица в консоли  ->  выбор моментов
                                                                    |
                                                                    v
                                             план клипов (JSON)  ->  mirv-скрипты
                                                                    |
                                                                    v
                                       HLAE поднимает CS2  ->  запись  ->  ffmpeg  ->  Highlighter/
```

## Что умеет

* Четыре группы правил детекции: мультикиллы, оружейные подвиги, клатчи, трюковые убийства
* Нарезка клипа на сегменты с пропуском простоя между убийствами
* Чистая картинка: настоящий игровой прицел без остального интерфейса
* Автоматический выбор аппаратного кодировщика (NVENC, AMF, QuickSync) с проверкой на работоспособность
* Фильтр по конкретному игроку
* Сам скачивает HLAE и ffmpeg при первом запуске

## Быстрый старт

### Готовый релиз

Положите демки в папку `demos` рядом с `HighlighterCS2.exe` и запустите:

```bash
HighlighterCS2.exe
```

HLAE и ffmpeg подтянутся сами в папку `tools`. Перед первым запуском закройте CS2, если она открыта.

### Из исходников

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python main.py
```

### Сборка релиза

```bash
.venv\Scripts\pip install pyinstaller
.venv\Scripts\python build.py
```

Результат в `dist/HighlighterCS2/`. Пересборка не трогает уже скачанный тулчейн, ваш `config.json`, логи, демки и записанные клипы.

## Команды

| Команда | Что делает |
| --- | --- |
| `HighlighterCS2.exe` | Показывает список найденных демок, даёт выбрать |
| `HighlighterCS2.exe match.dem` | Эта демка, моменты всех игроков |
| `HighlighterCS2.exe match.dem -p s1mple` | Только моменты этого игрока |
| `HighlighterCS2.exe match.dem -p -n1clxe` | Ники с дефиса работают как есть |
| `HighlighterCS2.exe match.dem -p 76561198000000000` | То же по SteamID64 |
| `HighlighterCS2.exe match.dem -v` | Подробный вывод в консоль |

**Про имя демки.** Полный путь не обязателен. Сначала проверяется файл рядом с exe, затем поиск идёт по папке `demos` и папкам демок CS2, включая вложенные. Расширение можно опустить: `dust1309` найдётся так же, как `dust1309.dem`. Если файла нет, программа покажет, где именно искала.

**Про ключ `--player`.** Он же `-p`, он же `--player-name`. Принимает точное имя, часть имени или SteamID64, регистр не важен. Ники, начинающиеся с дефиса, обрабатываются корректно: обычный разбор аргументов принял бы `-n1clxe` за флаг, поэтому аргументы нормализуются заранее. Настоящие флаги при этом не проглатываются, `-p -v` по-прежнему ошибка.

Если часть имени подходит нескольким игрокам, программа перечислит кому именно. Если никому, покажет весь состав демки.

## Как проходит работа

Каждый этап печатается отдельной строкой с номером, итогом и подробностями:

```
1/8 Reading match.dem
      OK de_dust2, 19 rounds, 10 players
2/8 Looking up 'n1clxe'
      OK -n1clxe (slot 2)
3/8 Scanning for highlights for -n1clxe
      OK 5 found

            здесь выводится таблица и запрашивается выбор

4/8 Planning clips
      work/plans/match.json
      OK 2 clips, 3 segments, 24s of footage
5/8 Launching Counter-Strike 2
      encoder h264_nvenc (hardware)
      HLAE injects the hook, then hands the game over
      OK game is up
6/8 Recording 2 clip(s) in 3 segment(s)
      the game closes itself after the last clip
      2/2 clips, elapsed 03:30
      OK 2 of 2 clips captured
7/8 Saving videos
      OK 2 of 2 clips written
8/8 Opening the output folder
      OK D:\...\Highlighter\match
```

Без `--player` шагов семь, поиск игрока пропускается. Во время записи прогресс печатается раз в 30 секунд. Папка с клипами открывается сама, это отключается ключом `recording.openOutputFolder`.

Упавший шаг помечается отдельно, поэтому сразу видно, на каком именно этапе всё встало.

### Сколько это занимает

Основное время уходит не на запись, а на движок:

| Этап | Порядок времени | Почему |
| --- | --- | --- |
| Внедрение HLAE | 2-3 секунды | Загрузчик внедряет хук и передаёт процесс игре |
| Холодный старт CS2 | 40-90 секунд | Инициализация движка, шейдеры, загрузка карты |
| Перемотка к первому клипу | зависит от тика | `demo_gototick` обязан просимулировать каждый тик от начала демки |
| Запись | зависит от длины | Идёт медленнее реального времени |

Перемотка это главный неочевидный расход: момент из первого раунда стартует почти сразу, момент из восьмого требует промотать четверть часа игры.

## Нарезка клипов

Раунд с тремя убийствами, между которыми по двадцать секунд беготни, это не хайлайт. Поэтому клип пишется не одним куском, а сегментами:

1. Сегмент открывается за `leadInSeconds` (2 с) до первого убийства
2. После каждого убийства камера держится ещё `gapHoldSeconds` (4 с) в ожидании следующего
3. Если следующее убийство попало в это окно, сегмент продолжается без склейки
4. Если нет, сегмент закрывается, игра перематывается, новый сегмент открывается за `resumeLeadSeconds` (1.5 с) до следующего убийства
5. Последний сегмент закрывается через `postRollSeconds` (2.5 с) после финального убийства

Разрез делается только когда перемотка гарантированно идёт вперёд. Порог равен `gapHoldSeconds + resumeLeadSeconds + seekLeadTicks`, по умолчанию 7.5 секунды.

> **Почему именно так.** Точка перемотки это начало следующего сегмента минус `seekLeadTicks`. При паузе короче порога она оказывается раньше конца текущего сегмента: игра прыгает назад, снова доходит до конца сегмента, снова прыгает назад. Получается вечный цикл. Поэтому все перемотки вычисляются на этапе генерации скриптов, и команда `demo_gototick` не пишется вовсе, если цель не строго впереди.

На тестовой демке нарезка убрала 58% пустого времени: клатч 1v2 длиной 72 секунды превратился в 15.5 секунды из трёх сегментов.

Сегменты пишутся отдельными файлами и склеиваются ffmpeg через concat-демуксер, без перекодирования.

## Настройка

Файл `config.json` создаётся при первом запуске рядом с программой. Недостающие ключи дописываются, ваши значения не трогаются.

Ключ `version` это версия схемы. При её росте применяются миграции: правятся только те ключи, формат которых изменился, остальные настройки сохраняются. В репозитории лежит шаблон `config.example.json`, сам `config.json` в git не попадает, чтобы ваши локальные пути не утекли.

### `debug`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `debug` | `false` | Выводить подробный лог в консоль |

Поставьте `true`, если что-то пошло не так и нужны детали: командная строка HLAE, переменные окружения, выбранный кодировщик, найденные слоты игроков, границы сегментов. То же самое даёт ключ `-v`, он имеет приоритет и включает вывод даже при `debug: false`.

В файл `logs/highlighter.log` подробности пишутся всегда. Этот флаг управляет только тем, видно ли их на экране.

## Под капотом

Половина команд из гайдов по CS:GO в CS2 просто не существует или работает иначе. Всё ниже проверено разбором строк в `client.dll`, `engine2.dll` и `AfxHookSource2.dll`.

### Запуск CS2 через HLAE

У HLAE **нет** запуска CS2 из командной строки. В бинарнике есть `ProcessArgsCsgoLauncher`, но аналога для CS2 не существует: диалог запуска CS2 доступен только из графического интерфейса. Поэтому игра поднимается через универсальный custom loader:

```
HLAE.exe -noGui -autoStart -customLoader
         -programPath "<cs2>/game/bin/win64/cs2.exe"
         -cmdLine     "-steam -insecure -afxDisableSteamStorage -sw -w 1920 -h 1080 +exec ... +playdemo ..."
         -hookDllPath "<hlae>/x64/AfxHookSource2.dll"
```

Custom loader сам Steam-окружение не выставляет, это делает приложение через `steamEnvironment`, иначе `cs2.exe` не стартует.

**HLAE это инжектор, а не супервизор.** Он внедряет хук, запускает игру и сразу завершается с кодом 0, ещё до того как CS2 успеет загрузиться. Поэтому приложение ждёт не HLAE, а сам процесс `cs2.exe`: опрашивает список процессов раз в секунду и убирает временные скрипты и настройки графики только после того, как игра закрылась. Если ждать HLAE, конфиги удаляются на второй секунде и команда `exec` в игре не находит ничего.

Пока идёт запись, CS2 должна быть единственной. Если игра уже запущена, приложение откажется стартовать и попросит её закрыть.

HLAE ищет ffmpeg не в `PATH`, а у себя в папке, поэтому файл `<hlae>/ffmpeg/ffmpeg.ini` пишется автоматически. Из путей с не-латинскими символами HLAE не работает, это проверяется до запуска.

### Команды CS2, которые легко перепутать

| Задача | CS:GO | CS2 |
| --- | --- | --- |
| Переключить камеру на игрока | `spec_player_by_accountid` | `spec_player <slot>`, слот равен `user_id + 1` |
| Удержать камеру | нет | `spec_lock_to_accountid <accountid>`, только удерживает уже выбранную цель |
| Отключить авторежиссёра | `spec_autodirector 0` | `spec_autodirector 0` |
| Вид от первого лица | `spec_mode 4` | `spec_mode 2`, нумерация другая |
| Убрать X-ray сквозь стены | нет | `spec_show_xray 0` |
| Убрать плашку перемотки демки | `demoui` | `demo_ui_mode 0` |
| Убрать надпись про TrueView | нет | `cl_trueview_show_status 0` |
| Не глушить звук при потере фокуса | нет | `snd_mute_losefocus 0` |

**Режимы наблюдателя в CS2 сдвинуты относительно CS:GO.** В CS2 их пять:

```
0 OBS_MODE_NONE   1 OBS_MODE_FIXED   2 OBS_MODE_IN_EYE   3 OBS_MODE_CHASE   4 OBS_MODE_ROAMING
```

В CS:GO были ещё `DEATHCAM` и `FREEZECAM` на местах 1 и 2, из-за чего `IN_EYE` был четвёртым. Поэтому `spec_mode 4` из любого гайда по CS:GO означает в CS2 **свободную камеру**, которая игнорирует цель и висит где попало.

### Наведение камеры

`spec_lock_to_accountid` только фиксирует уже выбранную цель, сам он наблюдателя никуда не переводит. Переключает камеру `spec_player`, описанный в игре как «Spectate a player by name or slot». Порядок важен: если выставить режим просмотра после выбора цели, камера уходит в свободный режим.

```
spec_autodirector 0
spec_mode 1              смена режима обязана идти первой
spec_player <slot>       слот равен user_id + 1
spec_lock_to_accountid <accountid>
spec_mode 2              IN_EYE
```

Слот читается из демки. Команда `spec_player` принимает и имя, но слот избавляет от проблем с кавычками и юникодом в никах. Всю последовательность можно переопределить в `spectateCommands`.

### Что попадает в кадр

| `captureMode` | Что видно |
| --- | --- |
| `crosshair` | Настоящий игровой прицел и больше ничего. По умолчанию |
| `clean` | Вообще ничего, кадр снимается до отрисовки интерфейса |
| `full` | Обычный игровой интерфейс целиком |

В режиме `crosshair` работают штатные cvar'ы для съёмки:

```
cl_drawhud 1
cl_draw_only_deathnotices 1        только прицел и килфид
cl_drawhud_force_deathnotices -1   убрать и килфид
```

Прицел при этом ведёт себя как в игре: прячется под прицелом AWP при зуме, раскрывается при движении, пропадает у ножа.

Режим `clean` использует отдельный поток с захватом до отрисовки Panorama:

```
mirv_streams add normal highlighterClean
mirv_streams edit highlighterClean record 1
mirv_streams edit highlighterClean capture beforeUi
mirv_streams record screen enabled 0
```

Весь двумерный интерфейс в CS2 рисует Panorama, поэтому в кадр не попадает ничего: ни интерфейс, ни радар, ни килфид, ни аватарки, ни всплывающие сообщения, ни плашка MVP. Прицела тоже не будет, он часть интерфейса. Этот режим удобен, если вы собираетесь накладывать свою графику в монтаже.

### Как CS2 пишет видео

В CS:GO кадры берут из потока `baseFx` через `mirv_streams edit`. **В CS2 этого потока нет вовсе**, там захват экрана, и он выключен по умолчанию:

```
mirv_streams settings add ffmpeg highlighterFfmpeg "... {QUOTE}{AFX_STREAM_PATH}/video.mp4{QUOTE}"
mirv_streams record screen enabled 1
mirv_streams record screen settings highlighterFfmpeg
mirv_streams record startMovieWav 1
```

Без `record screen enabled 1` HLAE исправно создаёт тейк и пишет `audio.wav`, но видео не появляется вообще. Переменная `{AFX_STREAM_PATH}` это **папка** потока, поэтому файл указывается как `{AFX_STREAM_PATH}/video.mp4`, а не `{AFX_STREAM_PATH}.mp4`.

### Настройки графики

При `applyHighGraphics: true` приложение правит `cs2_video.txt` в папке `userdata`:

* сначала делает резервную копию `cs2_video.txt.highlighter-backup`
* меняет **только уже существующие** ключи, новых не выдумывает, файл не ломается
* ставит `Autoconfig: 0`, чтобы CS2 не перезаписала настройки при старте
* после записи возвращает оригинал, если включён `restoreGraphicsOnExit`

Выключите `applyHighGraphics`, если хотите писать со своими настройками. Учтите, что CS2 сама переписывает этот файл во время работы, поэтому восстановление срабатывает только после закрытия игры.

### Разминка в демках

Поле `is_warmup_period`, которое отдаёт парсер, в проверенных демках CS2 всегда равно `False`, включая ножевой раунд разминки. Полагаться на него нельзя. Начало матча определяется по событию `begin_new_match`, всё что раньше отбрасывается.

## Требования

* Windows
* Counter-Strike 2
* Python 3.11 или новее, только для запуска из исходников
* Свободное место под сырые тейки в папке `work`

HLAE требует запуска CS2 с ключом `-insecure`. Это штатный режим для просмотра демок, на аккаунт он не влияет, но зайти в онлайн-матч в нём нельзя.
